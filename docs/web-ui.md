# Web UI

`distill ui` serves a local web app for browsing notes, topics, tags and stats, and for the
few edits Distill makes outside an agent: annotations, topic names and merges, and sync
conflicts. The server lives in `crates/distill-cli/src/ui/`.

## Address and lifetime

The UI is always at `http://distill.localhost:<ui.port>`. `distill init` picks the port once
(4777 when free) and never changes it, so links in notes and terminals keep working.
`distill config set ui.port <port>` moves it; links handed out earlier then break.

| Command | Does |
|---|---|
| `distill ui` | Starts the server in the foreground and opens an authorized browser tab. When a server is already running, only opens the tab |
| `distill ui --no-open` | Prints the authorization link instead of opening a browser |
| `distill ui --port <port>` | Serves on another port for this run. `PORT` does the same |
| `distill ui stop` | Stops the running server |

`distill mcp` starts the server in the background (`distill ui --background`, in its own
process group) before it returns note links from `distill_save` or `distill_recall`. It
writes the server's stderr to `<data dir>/ui/server.log`. Turn this off with
`distill config set ui.autostart false`. The server runs until `distill ui stop` or logout;
nothing registers it as a system service.

Only one server runs per port. Before binding, `distill ui` requests `/api/health`; a JSON
reply with `"app": "distill"` means a server is already there. When another program holds the
port, `distill ui` names it (process name and pid) and exits.

The server watches the vault it opened at start. After `distill vault use` or `vault move`,
run `distill ui stop` and start it again.

## Security

Any web page the user has open can send requests to a loopback port. The server:

- listens on `127.0.0.1` and `::1` only;
- answers only when `Host` is `distill.localhost`, `localhost`, `127.0.0.1` or `[::1]`
  (DNS rebinding), and otherwise returns 403;
- refuses any request whose `Origin` is not one of those hosts on its own port, and any
  non-GET request without an `Origin`, unless it carries the bearer secret. Every
  `*.localhost` port counts as the same site, so `SameSite` alone does not stop another local
  dev server from posting with the cookie;
- sends no CORS headers;
- requires the session secret on every `/api` route except `/api/health`.

The secret lives in `<data dir>/ui/secret` (mode 0600). A browser gets it as the
`distill_session` cookie (`HttpOnly`, `SameSite=Strict`, 400 days) by opening
`/auth?token=<token>`: `distill ui` writes a one-time token under `<data dir>/ui/tokens/` and
opens that URL. A token works once and expires after 5 minutes. The cookie is bound to the host
name it was set on, so authorize `distill.localhost`, not `localhost`. Tokens never go into
notes or links, since the vault syncs. The CLI sends the secret as `Authorization: Bearer`.

A browser without the cookie gets 401 from the API; the page then tells the user to run
`distill ui`.

## API

JSON over HTTP. Request and response types are Rust types in
`crates/distill-cli/src/ui/api.rs` and `crates/distill-core`; their TypeScript versions in
`apps/web/src/api/generated/` are generated by ts-rs when `cargo test` runs. Errors come back
as `{ "error": "<message>" }` with 400 (invalid input), 401, 403, 404 (unknown id) or 500.

| Route | Returns / does |
|---|---|
| `GET /api/health` | `Health`; no session needed |
| `GET /api/session` | `Session`: version, vault path, UI origin, whether the embedding model is installed |
| `GET /api/timeline?tag=&before=&limit=` | `TimelinePage`: notes newest first with question, ask position and annotation count; `next` is the cursor for `before` |
| `GET /api/notes?q=&tag=&limit=` | `NoteHit[]`: keyword search, or recent notes when `q` is empty |
| `GET /api/notes/{id}` | `NoteDetail` |
| `POST /api/notes/{id}/annotations` | Adds an annotation (`AnnotationInput`); returns the updated `NoteDetail` |
| `PUT` / `DELETE /api/annotations/{id}` | Rewrites (`AnnotationInput`) or deletes an annotation |
| `GET /api/topics` | `TopicCount[]`, most asked first |
| `GET /api/topics/{id}` | `TopicDetail`; a merged-away id returns the topic it resolves to |
| `PUT /api/topics/{id}` | Renames (`TopicRename`) |
| `POST /api/topics/{id}/merge` | Merges this topic into `TopicMerge.into`; returns `Merged` |
| `GET /api/topics/{id}/similar` | `SimilarTopic[]`; empty without the embedding model |
| `GET /api/duplicates` | `Duplicates`: topic pairs that are probably one question ([recall.md](recall.md)) |
| `POST /api/duplicates/dismiss` | Stops suggesting a pair (`PairDismissal`) on this device |
| `GET /api/tags` | `TagCount[]` |
| `GET /api/stats` | `Stats`, including notes per day and per agent |
| `GET /api/recall?q=` | `RecallResult` |
| `GET /api/problems` | `Problems`: sync conflicts and unreadable files |
| `POST /api/conflicts/resolve` | Keeps one copy (`ConflictChoice`) and moves the rest to `<data dir>/discarded/` |
| `GET /api/events` | Server-sent events: `changed` after every edit and every vault change on disk |
| `POST /api/shutdown` | Bearer secret only; used by `distill ui stop` |

Any other path serves the web app: files from `apps/web/dist` (embedded at build time), and
`index.html` for paths without a file extension. A build made without `apps/web/dist`
answers 503 with instructions.

## Not verified yet

`*.localhost` resolution on Linux and Windows. Chrome, Edge and Firefox resolve it
themselves; other browsers depend on the system resolver. On macOS the system resolver maps
`distill.localhost` to `::1`, which is why the server also listens there.
